Áp dụng cả v1 & v2
Fundamentals

AI Connector là gì, hoạt động ra sao

Nếu chưa quen với khái niệm MCP / Remote Connector, đọc phần này trước. Ai đã dùng Claude Desktop connectors rồi có thể skip xuống Kiến trúc.

🔌 Analogy — USB cho AI

Trước khi có USB, mỗi thiết bị ngoại vi (chuột, bàn phím, máy in…) dùng cổng riêng. Nhà sản xuất phải làm N driver, người dùng phải cắm N cổng. USB làm chuẩn hoá: 1 giao thức, mọi thiết bị.

MCP (Model Context Protocol) = USB cho AI. Trước đây mỗi AI app tự implement cách gọi tool/API riêng. MCP làm chuẩn hoá — server (như OneMCP) expose tools + resources theo giao thức chuẩn, mọi AI client (Claude Desktop, ChatGPT, Cursor) đều cắm được không cần viết integration riêng.

Remote MCP Connector là biến thể chạy qua HTTP (thay vì stdio local), có thêm OAuth 2.1 để authenticate user + phân quyền. OneMCP v2 là Remote MCP Connector cho phòng KT.

Khái niệm cốt lõi

MCP Server

Backend expose tools (functions callable), resources (data readable), prompts (templates) qua giao thức MCP.

OneMCP = MCP server. Expose list_skills, search, submit_artifact…

MCP Client

AI app / IDE / agent gọi tool trên MCP server. Tự động discover tools list, feed vào context của LLM.

Claude Desktop, ChatGPT app, Cursor IDE, custom scripts qua mcp-remote.

Transport

Cách client & server nói chuyện. 2 loại: stdio (local process) và Streamable HTTP (remote qua HTTP + SSE).

OneMCP dùng Streamable HTTP (spec 2025). Endpoint /mcp, header Mcp-Session-Id.

JSON-RPC 2.0

Format wire chuẩn: { jsonrpc, method, params, id }. Method như tools/list, tools/call.

Streaming response qua SSE cho long-running tools.

OAuth 2.1 + DCR

Chuẩn auth cho Remote Connector. Dynamic Client Registration (RFC 7591) = AI client tự đăng ký OAuth client với server, không cần cấp secret thủ công.

Server expose .well-known/oauth-authorization-server metadata. Client tự phát hiện endpoints.

Consent screen

User login → thấy màn xin quyền: "OneMCP muốn truy cập tools + skills của bạn". Allow → nhận access token.

OneMCP: coarse consent (1 lần cho toàn bộ tools) trong v2. Fine-grained per-tool defer.

Ví dụ .well-known metadata

AI client fetch endpoint này trước để biết OAuth flow của OneMCP:

# GET https://mcp.inet.vn/.well-known/oauth-authorization-server
{
  "issuer": "https://mcp.inet.vn",
  "authorization_endpoint": "https://mcp.inet.vn/oauth/authorize",
  "token_endpoint": "https://mcp.inet.vn/oauth/token",
  "registration_endpoint": "https://mcp.inet.vn/oauth/register",      // DCR
  "scopes_supported": ["mcp:tools", "mcp:resources"],
  "response_types_supported": ["code"],
  "grant_types_supported": ["authorization_code", "refresh_token"],
  "token_endpoint_auth_methods_supported": ["client_secret_basic"],
  "code_challenge_methods_supported": ["S256"]                     // PKCE
}

Tại sao chuẩn hoá quan trọng

🔌 Zero-friction cắm client

User chỉ paste URL, không cần config secret thủ công. DCR + OAuth flow tự động.

🔐 Auth chuẩn

OAuth 2.1 = same standard toàn ngành. Không phải reinvent auth mỗi lần. Có refresh token rotation, PKCE, revoke chuẩn.

🌐 Ecosystem lock-out-free

Đổi AI client (Claude → ChatGPT → Cursor) không cần build lại integration. Server không đổi.

Skills vs Artifacts — phân biệt

📘 Skills (per-project)

Static protocol / guide / SOP — do project maintainer viết trong git repo của project.

  • • Source: 1 git repo per project (isolation, deploy token riêng)
  • • Sync tự động (webhook + BullMQ per-project queue)
  • • Format: manifest.json + SKILL.md
  • • Scope: public (all users) · dept · private
  • • Visibility flag: default (list_skills show) · restricted (chỉ khi search hit)
  • • Ví dụ: debug-guide, session-wrapup, deploy-onelog-vps

📄 Artifacts (user-generated)

Runtime knowledge — dev submit qua MCP hoặc portal.

  • • 3 loại: report · research · kb
  • • Template validate structure
  • • Versioning (append-only)
  • • Review flow: pending → published
  • • Attachments PDF/PNG… ≤100MB (MinIO)
  • • Scope theo project + dept của người submit

Multi-project

Đăng ký dự án đẩy skills lên OneMCP

Mọi dự án phòng KT (OneLog, OneMCP, authway, các vibecode app…) đều đẩy skills + KB qua OneMCP. Onboarding qua portal, dept-admin approve.

1 · Dev đăng ký project

  1. Login portal mcp.inet.vn qua Zimbra SSO
  2. New Project → điền: name, git repo URL, scope (public/dept/private)
  3. Portal generate deploy token + webhook URL
  4. Dev add webhook + token vào GitLab/GitHub repo settings
  5. Push commit đầu tiên → webhook trigger sync

2 · Dept-admin approve

  1. Portal → Pending Projects list
  2. Review scope + git repo hợp lệ không
  3. Approve → BullMQ queue kick off first full sync
  4. Reject với reason → dev sửa và resubmit
  5. Approved project auto-sync mỗi khi push

Artifacts — không lưu local

📄 Push Artifacts — spaces model (v1 actual)

Artifact gắn với 1 space. Space = workspace theo dept/topic (VD ops-runbook, ops-oncall). Visibility space (chỉ members) · dept (toàn dept) · cross_dept (mọi dept). Access check ở service layer.

Kênh 1

Từ AI session (recommended)

Agent tự đề xuất khi kết thúc session. User confirm → agent gọi submit_artifact qua MCP.

Ưu điểm: có context đầy đủ, template auto-fill qua get_artifact_template. Ít friction nhất.

Kênh 2

Portal web form

Portal /artifacts/new → chọn space + type → fill structured form theo template → upload attachments → submit.

Ưu điểm: dev draft chậm, review preview trước submit, upload attachments dễ.

Kênh 3

REST API (advanced)

POST /api/artifacts với header X-Onemcp-User (v1) hoặc Bearer token (v2). Dùng cho CI/CD, script.

Ưu điểm: batch import, auto-generate KB từ postmortem tool.

  • • Manifest fields: thêm 2 fields dùng thực tế — scope (public/dept/private) và visibility (default/restricted). v1 có schema nhưng chưa dùng.

Debug bug end-to-end

6 bước từ khi gặp error đến khi KB dùng chung được cho toàn công ty.

1
Gặp error Paste stacktrace/log vào Claude Desktop chat, mô tả context (endpoint gọi, khi nào xảy ra).
2
Agent search qua OneMCP Agent tự động gọi search với keywords → hit KB từ project A/B/C bất kỳ user có quyền. Nếu hit → apply thẳng, skip debug.
3
Load guide nếu cần Nếu chưa có KB, agent gọi load_skill debug-guide để lấy protocol 6-step: stabilize → gather → reproduce → isolate → fix → wrap-up.
4
Fix theo protocol Agent hỗ trợ debug + code. Bạn confirm mỗi bước quan trọng (không apply blind).
5
Wrap-up KB Trước khi close session, agent gọi get_artifact_template kb → điền problem/solution/related → submit_artifact.
✓
Maintainer review → Published Trong ngày, maintainer approve. KB scope theo project visible qua search. Dev khác dùng ngay.

FAQ

Câu hỏi thường gặp

Khi nào v2 OAuth Connector ship? ▾

Sau khi plan 260805-1409 onemcp-migrate-gitlab-to-zitadel hoàn tất (Zitadel SSO thay GitLab SSO). Plan 260805-0852 ai-connector-hub ở trạng thái BLOCKED chờ. Effort ~14-18 ngày dev sau khi unblock.

Đang dùng v1 header trust, cần làm gì khi v2 ship? ▾

v1 & v2 song song 1 khoảng transition. v2 ship xong, dev tự chuyển AI client sang Remote Connector (login lại 1 lần qua Zimbra), remove X-Onemcp-User header. v1 endpoint sẽ deprecated sau 4 tuần.

Data có leak sang phòng ban khác không? ▾

Không. RBAC 3-layer enforce ở service layer. Project scope dept/private filter theo user's Zitadel identity + Zimbra department mapping.

Project mới đẩy skills mất bao lâu approve? ▾

Dept-admin review trong ngày. Sau khi approve, first-sync qua BullMQ trong vài giây. Push commits sau đó auto-sync qua webhook.

Nhỡ submit artifact sai thì sao? ▾

Artifact là append-only versioning. Edit tạo version mới, maintainer có thể publish version cũ nếu cần rollback.

AI client nào hỗ trợ v2 OAuth Connector? ▾

Claude Desktop native (primary target). ChatGPT + Cursor test matrix trong Phase 5. Client cũ không support Streamable HTTP → dùng mcp-remote proxy fallback.

MCP tool aggregator từ project khác có không? ▾

v2 KHÔNG có (out-of-scope, xem non-goals plan). Trigger mở lại: ≥ 2 project confirm cần share tool giữa các phòng. v2 focus: skills registry + KB share qua artifacts.

Khi nào có semantic search? ▾

v2.1 roadmap — pgvector đã enable, cần chọn embedding infra (Ollama local? cloud?). Feedback pilot v2 sẽ quyết định ưu tiên.

Nếu OneMCP down thì AI client còn dùng được không? ▾

Có. AI client core (Claude Desktop) hoạt động bình thường, chỉ không gọi được tools OneMCP cho tới khi service back up. Emergency rollback: AI_CONNECTOR_MODE=off disable OAuth endpoint, portal vẫn work qua session cookie.

Backup có tự động không? ▾

Có. Daily pg_dump + MinIO mirror, retention 14 ngày. Off-site mirror (NAS/S3) auto hoá sau v2 rollout.
